# Output Contract

## Overview

This document defines the output files and artifacts generated by Repo Manager
during Pulp deployment, content download, and status generation operations.

## Output Files

### 1. repo_status.yml

### 2. Download Status CSV

**Location**: `/opt/omnia/repo_manager/output/<project_name>/status.csv`

**Purpose**: Tracks download status of each software item

**Structure**:

```csv
name,type,arch,status,repo_name,distribution_url,timestamp
slurm,rpm,x86_64,success,slurm_x86_64_rhel_10_0,https://...,2026-07-30T12:00:00Z
geopm,tarball,x86_64,success,geopm_x86_64,https://...,2026-07-30T12:05:00Z
```

**Fields**:
- `name`: Software name
- `type`: Content type (rpm, tarball, etc.)
- `arch`: Architecture (x86_64, aarch64)
- `status`: Download status (success, failed, partial)
- `repo_name`: Pulp repository name
- `distribution_url`: Pulp distribution URL
- `timestamp`: Download timestamp

### 3. Validation Logs

**Location**: `/var/log/omnia/repo_manager/repo_manager.log`

**Purpose**: Detailed logs of validation operations

**Content**:
- Validation results
- Error messages
- Warning messages
- Debug information

### 4. Pulp Configuration Files

**Location**: `/opt/omnia/pulp_config/pulp/settings/`

**Purpose**: Pulp server configuration files

**Files**:
- `pulp_settings.yaml`: Main Pulp configuration
- `certs/`: SSL/TLS certificates
  - `pulp_webserver.crt`: Server certificate
  - `pulp_webserver.key`: Server private key

### 1. Deploy Phase

**Outputs**:
- Pulp container configuration
- Pulp settings files
- SSL/TLS certificates
- System-wide Pulp CLI symlink

### 2. Download Phase

**Outputs**:
- Pulp repositories
- Pulp distributions
- Download status CSV
- Download metadata

### 3. Status Generation Phase

**Outputs**:
- repo_status.yml
- Distribution mappings
- URL configurations


**Validation Checks**:

## Output File Consumption

### By Image Build Manager

**Usage**: Image Build Manager reads `repo_status.yml` to:
- Access RPM repository URLs
- Get certificate paths for HTTPS access
- Determine OS version and type
- Configure image build processes

**Example Integration**:
```yaml
# In image_build_manager
repo_status_file: "/opt/omnia/repo_manager/output/project_default/repo_status.yml"
rpm_repos: "{{ lookup('file', repo_status_file) | from_yaml | rpm_repos }}"
```

### By Cluster Nodes

**Usage**: Cluster nodes use `repo_status.yml` to:
- Configure package managers (dnf, yum)
- Access offline repositories
- Verify SSL certificates
- Configure container registries

## Output File Backup

**Recommended Backup Strategy**:

```bash
# Backup output directory
tar -czf repo_manager_output_backup_$(date +%Y%m%d).tar.gz \
  /opt/omnia/repo_manager/output/<project_name>/

# Backup to remote location
scp repo_manager_output_backup_*.tar.gz backup-server:/backups/
```

## Output File Retention

**Retention Policy**:
- Current output: Keep indefinitely
- Previous outputs: Keep for 30 days
- Backup archives: Keep for 90 days

**Cleanup Script**:
```bash
# Remove outputs older than 30 days
find /opt/omnia/repo_manager/output/ -mtime +30 -exec rm -rf {} \;
```

## Output File Permissions

**Recommended Permissions**:
- repo_status.yml: `644` (rw-r--r--)
- status.csv: `644` (rw-r--r--)
- Output directory: `755` (rwxr-xr-x)
- Pulp settings: `600` (rw-------) for sensitive files

**Owner**: `root:root` (or appropriate system user)

## Output File Security

### Sensitive Information

**Protected Data**:
- Pulp credentials
- SSL/TLS private keys
- Authentication tokens

**Protection Measures**:
- Restrict file permissions
- Use Ansible Vault for secrets
- Enable filesystem encryption
- Regular security audits

### URL Security

**HTTPS Enforcement**:
- All repository URLs use HTTPS
- Certificate validation enabled
- Self-signed certificates properly configured

## Output File Monitoring

### Health Checks

**Monitoring Scripts**:
```bash
# Check if repo_status.yml exists and is valid
if [ -f /opt/omnia/repo_manager/output/<project_name>/repo_status.yml ]; then
  echo "repo_status.yml exists"
  python3 -c "import yaml; yaml.safe_load(open('/opt/omnia/repo_manager/output/<project_name>/repo_status.yml'))"
else
  echo "ERROR: repo_status.yml missing"
  exit 1
fi
```

### Automated Alerts

**Alert Conditions**:
- repo_status.yml missing or invalid
- Download failure rate > 5%
- Pulp service unavailable
- Certificate expiration approaching
