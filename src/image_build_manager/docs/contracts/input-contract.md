# Image Build Manager -- Input Contract

**Domain**: `image_build_manager` | **Collection**: `omnia.image_build`

---

## 1. image_build_config.yml

**Purpose**: Domain configuration for image builds.

**Source template**: `src/image_build_manager/input/image_build_config.yml`

**Runtime location**:
`<IMAGE_BUILD_MANAGER_DATA_PATH>/input/<project>/image_build_config.yml`, or
`<OMNIA_DATA_PATH>/image_build_manager/input/<project>/image_build_config.yml`
when the domain-specific path is unset.

**Schema**: `plugins/module_utils/input_validation/schema/image_build_config.json`

| Field | Type | Required | Shipped value | Description |
|-------|------|----------|---------------|-------------|
| `s3_configurations.provider` | string | Yes | `"minio"` | `minio` (local) or `powerscale` (external) |
| `s3_configurations.endpoint_url` | string | Yes | `""` | Must be empty for MinIO and an HTTP(S) URL for PowerScale |
| `repo_manager_output_path` | string | Yes | Project path placeholder | Full path to upstream `repo_status.yml`; placeholders are resolved while staging |
| `image_build_type` | string | Yes | `"image-thrillhouse"` | `image-builder` or `image-thrillhouse` |
| `functional_groups_source` | string | Yes | `"catalog"` | `config` uses `package_groups.yml`; `catalog` uses `CATALOG_FILE_PATH` |
| `build_image.max_parallel` | int | Yes | `0` | Concurrent compute builds; 0 means all at once |
| `build_image.build_timeout` | int | Yes | `7200` | Per-build timeout in seconds; range 600-86400 |
| `build_image.force_rebuild` | bool | Yes | `false` | Bypass the package-hash cache |
| `build_image.backup_s3_images` | bool | Yes | `false` | Copy existing compute artifacts to a `_prev` prefix before rebuilding |
| `build_image.repo_ssl_verify` | bool | Yes | `true` | Enable TLS certificate and repository GPG verification |
| `aarch64_inventory_host_ip` | string | No | `""` | ARM host IPv4 address; empty disables aarch64 builds |
| `aarch64_ssh_user` | string | Conditional | `"root"` | Required when an ARM host IP is configured |

JSON Schema `default` annotations do not populate missing YAML keys. Every field
marked required must be present in the staged input.

## 2. image_build_credentials.yml

**Purpose**: Vault-encrypted credentials for S3 and SSH.

**Location**: Runtime `input/<project>/image_build_credentials.yml`

**Generated by**: `collect_build_credentials` role (interactive prompts)

**Vault key**: Runtime `input/<project>/.image_build_credentials_key`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `s3_access_id` | string | PowerScale only | PowerScale S3 access key ID; MinIO uses `admin` when empty |
| `s3_secret_key` | string | Yes | MinIO root password or PowerScale S3 secret key; minimum 8 characters |
| `aarch64_ssh_password` | string | When ARM is enabled | Password used to install the controller's SSH public key |

## 3. repo_status.yml (upstream contract)

**Purpose**: RPM repo URLs, OS metadata, and certificate paths from `repo_manager`.

**Producer**: `repo_manager` domain

**Location**: Path from `repo_manager_output_path` in config

### Supported Format

The build flow validates `repo_status.yml` against `repo_status.json` before it
parses the file. The consumer contract covers only the fields required by Image
Build Manager. Other top-level fields, producer metadata, and architectures are
ignored so Repo Manager can evolve them independently. Repository data uses the
`repositories.<version>.<architecture>.<repository>.url` format. Legacy-only
`rpm_repos`/`user_repos` documents do not pass the preceding contract validation.

### Key Fields Consumed

| Field | Required | Purpose |
|-------|----------|---------|
| `overall_status` | Yes | Must be `"success"` to proceed |
| `cluster_os_type` | Yes | Build target OS type (e.g. `rhel`) |
| `repositories.{version}.{arch}` | Yes | RPM repository objects for supported architectures |
| `repositories.{version}.{arch}.{repository}.url` | Optional per entry | HTTP(S) URL consumed when present; at least one usable x86_64 or aarch64 URL is required |
| `repositories.{version}.{arch}.{repository}.priority` | No | Repository priority consumed when present |
| `repo_manager.port` | No | Managed repository port; otherwise derived from a repository URL |
| `repo_manager.certificates.server_crt` | No | CA certificate path; certificate handling is skipped when absent or empty |

`repo_config`, `execution_contexts`, `overall_status_by_version`, `registries`,
`file_repos`, unknown architectures, and other producer-owned fields are not
validated or consumed. Repository key order determines the reported version
order.

### Validation Rules

| Rule | Error |
|------|-------|
| File must exist | `repo_status.yml not found` |
| `overall_status` = `"success"` | `repo_manager did not complete successfully` |
| At least one supported-architecture repository URL exists | `repositories must contain at least one non-empty x86_64 or aarch64 repository URL` |
| Certificate file exists (if path set) | `repo manager certificate not found` |

## 4. package_groups.yml (config mode)

**Purpose**: OS metadata and RPM package mapping per functional group (config mode only).

**Location**: `input/<project>/package_groups.yml`

**Used when**: `functional_groups_source: "config"`

When this file remains staged in catalog mode it is not consumed for package
resolution, but the input validator still schema-checks it.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `os` | string | Yes | OS type (currently `rhel` in the shipped input). Sets `cluster_os_type`. |
| `os_version` | string | Yes | Numeric dotted OS version (for example `10.0`). Sets `cluster_os_version` and `rhel_tag`. |
| `base_packages` | list[string] | Yes | RPMs installed in every image |
| `functional_groups.<name>.packages` | list[string] | Yes | Additional RPMs per group |

Functional groups are derived from the keys in `functional_groups` dict, filtered by
architecture suffix (`_x86_64` / `_aarch64`). No separate group list is needed in
`image_build_config.yml`.

The schema accepts a non-empty OS string, but the current build tasks and image
templates are RHEL-oriented. The comments about other operating systems in the
source template describe future work, not a currently supported build path.

## 5. catalog JSON (catalog mode)

**Purpose**: Full package catalog with three-level resolution (functionallayer -> groups -> packages).

**Producer/source**: Catalog preparation outside this domain; the main setup
script stages sample catalogs under `<OMNIA_DATA_PATH>/catalog/`

**Location**: Path from `CATALOG_FILE_PATH` environment variable

**Used when**: `functional_groups_source: "catalog"`

### Key Fields Consumed

| Field | Purpose |
|-------|--------|
| `catalog.identifier` | Catalog identity for traceability |
| `catalog.functionallayer[]` | Layer definitions with components |
| `catalog.groups.{name}` | Group definitions with component keys |
| `catalog.packages.{key}` | Package metadata (name, packagetype, sources) |

### Layer Classification

Layers are classified as **base OS** or **compute** by their **name prefix**:

| Pattern | Classification | Result |
|---------|---------------|--------|
| Name starts with `baseos` | Base OS | Packages -> `base_image_packages` |
| Any other name | Compute | Non-baseos packages -> `compute_images_dict` |

Compute layers that reference `baseos_group_*` components extract `os_version` and
`os` (OS type) but skip those packages (already in the base image).

### Module Return Values (catalog mode)

| Field | Type | Description |
|-------|------|-------------|
| `catalog_identifier` | string | Catalog identity string for traceability |
| `cluster_os_type` | string | OS type from baseos group's `os` field (e.g. `rhel`) |
| `cluster_os_version` | string | Primary OS version from first baseos group |
| `cluster_os_versions` | list[string] | All unique OS versions across baseos groups |
| `base_image_packages` | list[string] | Deduplicated RPM names from baseos layers |
| `compute_images_dict` | dict | Keyed by layer name, each with `functional_group`, `packages`, `os_version` |
| `layer_count` | int | Number of functional layers matching build_arch |
